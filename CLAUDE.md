# Kamus (dictionary tool) - project rules

## Keep the credits up to date (shown on the Settings page)
`credits.json` lists every library, data source, online service, font/icon set and TTS engine this project uses,
with its licence. It is rendered on the **Settings → Legal information** page (`#legal`) via `/api/credits`: numbered sections (content & data, online services, open-source software grouped by licence, models with usage restrictions, fonts/icons/design, trademarks). Entries need `kind` (data/service/software/asset), `name`, `license` (use SPDX-style ids like `MIT`, `Apache-2.0` so they link to the licence text), `role`; add `attribution` for content that requires an attribution notice. A `license` containing 'non-commercial' lands in the restricted-models section.

**Whenever you add, remove, upgrade across a licence change, or swap any of these, update `credits.json` in the same change**
(and bump its `updated` date):
- a Python package (`requirements.txt`, or inside `.tts-env`)
- a dictionary/content source (KBBI, Wiktionary, Tatoeba, ...)
- an online service or API (edge-tts, Google Fonts, ...)
- a TTS engine or model (and its terms, e.g. the non-commercial Wikidepia model)
- a font, icon set or design system loaded by `static/index.html`

Check licences from the project's own metadata or repo, not from memory; if unsure, say so in the entry's `note`.

## Layout
- `server.py` - stdlib HTTP server. `.venv/bin/python server.py` = this computer only; `--lan` = whole local network; `--cert/--key` = https; `--port N`. http://localhost:8765
- `kbbi.py`, `wiktionary.py` - source parsers (Tatoeba has no server module any more); `pronounce.py` - approximate IPA
- Cards live in the BROWSER (IndexedDB 'kamus-cards', `static/cards-store.js`; ids = sha1(word|meaning)[:12], same rules as the old cards.py). `cards.db` is the OLD server store: kept read-only (`/api/cards`) so each browser copies it once (`migrateFromServer`); never delete it until every browser you use has migrated. `cache.db` is the disposable cache. `static/anki-model.json` = the Anki note type 'Kamus v1' (fields + 4 card templates; the single source for the page, AnkiConnect and the .apkg export). `static/apkg.js` builds the .apkg in the browser with sql.js + JSZip (`static/vendor/apkg/`, see scripts/fetch_vendor.sh)
- `wikidepia.py` + `wikidepia_worker.py` - optional offline TTS (needs `.tts-env`, see `scripts/install_wikidepia.sh`)
- `static/index.html` - the whole UI (Material Design 3): views Kamus / Anki / Settings via #hash
- `static/sw.js`, `manifest.webmanifest`, `icon.svg`, `icons/` - PWA (installable, offline shell + cached lookups/audio). Bump `VERSION` in sw.js when its caching logic changes
- `static/wd-worker.js` + `static/vendor/ort/` (onnxruntime-web 1.31.1 WASM build, copied from the npm package; refresh with `npm pack onnxruntime-web`) + `models/wikidepia-v1.2/web/` (vits.onnx, tokens.json, speakers.json: made by `scripts/export_wikidepia_onnx.py`) = Wikidepia running inside the browser. Only text->phonemes (`/api/phonemize`) stays on the server.
- Wiktionary and Tatoeba are fetched by the BROWSER (`wikiLookup`/`wikiSuggest`/`tatoebaLookup` in index.html; Wiktionary's API and the new api.tatoeba.org/v1 send CORS headers; the old tatoeba.org/api_v0 did not). KBBI sends none, so it stays server-side.
- The server sends COOP `same-origin` + COEP `credentialless` on every response (cross-origin isolation = multi-threaded WASM). Anything new that is loaded cross-origin must work under COEP credentialless.
- `static/theme.js`: seed colour -> Material 3 tokens (own OKLCH implementation, approximates Material's HCT; the default purple #6750a4 keeps Material's exact baseline values). It must be loaded AFTER the main <style> so its :root block wins; the saved theme is applied before first paint.
- Speech speed (Settings, 0.5-1.5): browser `rate`, edge-tts `rate=±N%`, Wikidepia `length_scale = 1/speed` (server worker and in-browser scales[1]). Cache keys keep the old form at speed 1, and Anki cards / .apkg always use normal speed.
- UI rules the user cares about: text fields = Material filled fields; pickers/menus must look like menu buttons (outlined pill + arrow), never like a text field; the search bar's open state is a JS class (`.open`), not `:hover` (touch screens have sticky hover).
- Elevation: the search bar (level 3) is the highest floating element; everything else stays lower (sheets level 2, floating contents/chip level 1) and the dock's z-index (45) is above all of them. Do not give other elements the bar's elevation.
- Speaker buttons: class `loading` shows the Material 3 loading indicator (a JS-morphing shape, see `liPath`), `speaking` shows a stop icon; tapping a loading/speaking button stops it.
- HTTPS: browsers only allow PWA install, Cache Storage-style APIs and multi-threaded WASM on secure origins. The owner reaches the server over Tailscale (MagicDNS name like `<host>.<tailnet>.ts.net`); the fix is `tailscale serve --bg --https=443 http://127.0.0.1:8765` after enabling HTTPS in the Tailscale admin console (`CertDomains` was empty). The server treats `X-Forwarded-Proto: https` as secure. Do not run `tailscale serve` yourself: it exposes a service and needs the user's approval.
- 'Your cards' (sec-mine) shows saved cards for the looked-up word (English meaning + Anki state) above the KBBI result.
- Anki connection UI: a status chip in the title bar (Anki page only): 'Connected'/'Disconnected' + coloured dot; hover or tap expands it (connected: Sync, Export, divider, info; disconnected: info only). The info icon opens `#ankiDlg` (native `<dialog>`) with status, AnkiConnect setup and the secondary actions (Check again, Refresh progress, Sync with AnkiWeb, Export).
- Translation (Settings → Translation): `translate.py` with engines `mymemory` (default, web API; called by the BROWSER directly via `mymemoryText` in index.html, results cached in IndexedDB; `translate.py` keeps a server-side copy), `argos` (offline, own env `.argos-env` via `scripts/install_argos.sh`, worker `argos_worker.py`) and `libretranslate` (URL/key from Settings). The New/Edit card sheet auto-fills a missing translation (Example↔ExampleEN, KBBI↔Wiki) and marks it 'Auto-translated'; hand edits are never overwritten. Results are cached in cache.db table `tr`.
- In-browser translation (engine `opusmt`): `static/tr-worker.js` runs Opus-MT (Xenova ONNX, quantized, `models/opus-mt/` via `scripts/download_opus_mt.sh`, about 108 MB per direction) with Transformers.js (`static/vendor/transformers/transformers.min.js` = the BUNDLED build; the `.web` build leaves bare `onnxruntime-*` imports and fails; WASM runtime copied from the same npm package). Settings downloads the files (from this server's `models/opus-mt/` when it has them, else straight from Hugging Face, which sends CORS headers; sizes are checked against `MT_SIZES`) into IndexedDB (`models` store, key `mt:<path>`); the worker's `fetch` hook serves them from there, so the library must be imported dynamically AFTER the hook. Argos itself cannot run in a browser; this is its client-side equivalent.
- Editing cards: `cards.update` keeps the card id and note_id and sets `dirty` when the card is already in Anki; the browser pushes it with AnkiConnect `updateNoteFields` (immediately if connected, else on the next Sync). Progress is matched to cards by note id first.
- KBBI writes the headword inside examples/definitions as `~` or `--`; `kbbi.py` replaces both with the entry's headword. Changing KBBI parsing = bump the `cache4` table name in server.py.
- Pronunciation text: `cleanIpa` strips combining marks (e.g. U+032A dental mark) - no web font supplies them and many systems show boxes.
- Wikidepia TTS notes: GPU is not usable here (GT 750M, compute 3.0, no NVIDIA driver), CPU only; model dir `models/wikidepia-v1.2/`

## Anki bridge (static/index.html, 'Anki' view)
- One note = one word + one meaning (index: `Word | meaning`), 4 cards. Change fields/templates only in `static/anki-model.json` and bump its `name`.
- Cards are stored in the browser first (they are per browser/origin: localhost and a Tailscale address do NOT share cards; move them with a backup file); AnkiConnect is called from the *browser* to the Anki desktop on the same device (needs `webCorsOriginList` to include the page origin; AnkiConnect's default port 8765 clashes with Kamus on the same computer -> run Kamus with `--port`).
- Not testable against real Anki in this environment: the flow was tested against a mock AnkiConnect (CORS, duplicates, audio download, review stats).

## Card types, theme mode, selection lookup (later additions)
- Per-note card types: fields `Skip1..Skip4` (non-empty = no card N). Every template Front is wrapped in `{{^SkipN}}…{{/SkipN}}`, so old notes (empty Skip) are unchanged. The browser's `ensureAnkiModel` adds the fields to an existing 'Kamus v1' model (`modelFieldAdd` + `updateModelTemplates`) before sync/edit pushes. Not tested against real Anki: re-enabling a card relies on Anki generating the missing card when the note is updated.
- 'Desynced' (orange badge, `--warn-container` tokens) = card is in Anki but edited here (`dirty`).
- Light/dark: `KamusTheme.setMode('light'|'dark'|'system')` stamps `<html data-theme>`; token blocks exist for bare `:root`, `prefers-color-scheme` guarded by `:not([data-theme=light])`, and `[data-theme=dark]` (both in index.html and theme.js `css()`).
- Selection chip (`qchip`): works in #out, #qsheet, #ankiList, #viewLegal; text inside `lang="en"` elements gets an Indonesian translation (trText en→id) instead of a Wiktionary lookup. Tag English content with `lang="en"`.
- Beware when editing CSS with string replaces: `.qchip` and `.mine-chip` rules are near-identical.
- apkg.js was checked by importing its output with the real `anki` Python package (pip install anki; `Collection.import_anki_package`): 37 notes, 144 cards, media, fields and Skip flags came through. A card is only made when its template's front renders non-empty (genanki's `req` logic would have made none with the SkipN fields).
- Backup: Anki dialog -> 'Back up cards' downloads `kamus-cards-backup-DATE.json` ({kamus_cards:1, cards:[...]}), 'Restore from backup…' adds the cards whose id is missing (it never overwrites). Browser storage is per origin and can be evicted, so remind the user to back up.
- Settings -> 'Storage in this browser' (`renderStorage`): navigator.storage.estimate() + per-store sizes (`idb.stats`), with Clear/Remove/Back up/Protect buttons. Cards: `KamusCards.stats()`.
- Anki dialog -> 'Import from Anki' (`importFromAnki`): adds notes of the 'Kamus v1' note type that Kamus lacks (matched by note id; a same word+meaning card is linked, not duplicated). It never updates cards Kamus already has, and other note types are not imported.
- Cloud sync (optional, `static/sync.js`): the user's OWN Firebase project (config pasted in Settings -> Sync, stored in localStorage `kamus-fb`; Google sign-in only; Firebase compat SDK in `static/vendor/firebase/`, loaded only when a config exists). Pull (`updated > lastPull`) -> `KamusCards.applyRemote` (newest `updated` wins; a changed card that is in Anki becomes dirty) -> push cards whose `sync_u !== updated` -> merge history (`mergeHistory`, tombstone `kamus-history-cleared`). Deleted cards stay as tombstones (`deleted:true`). Note ids/progress never sync. Rules: `firestore.rules`. Tested with a fake cloud in two browser contexts (`KamusSync.syncCore`); the Firebase adapter itself (Google sign-in popup, Firestore calls) could NOT be tested here (no Firebase project): only SDK loading and the 'invalid apiKey' message were.
- Google sign-in runs on `/auth.html` (top-level page; the server omits COOP/COEP for exactly that path). Reason: with COOP same-origin (sent on https/localhost for WASM threads) the page cannot talk to the Firebase pop-up and signInWithPopup fails with 'popup closed / cancelled'. After sign-in the page returns to `/#settings`; Firebase keeps the user in this origin's IndexedDB. Never add COOP to /auth.html.
- Sharing the sync config: `KamusSync.shareUrl()` = `<origin>/#sync=<base64url(apiKey|authDomain|projectId|appId)>`, drawn as a QR (`static/vendor/qr/qrcode.js`, qrcode-generator) in Settings -> Sync; the receiving device opens the link (`handleSyncHash`) or scans it in-app (`startSyncScan`, jsQR, needs getUserMedia = https/localhost) and confirms in `#syncImpDlg`. The hash is removed from the address bar immediately. The QR holds project settings only (not secrets).
- AGPL section 13: `SOURCE_URL` in static/index.html (Legal page -> 'Kamus licence and source code') points at the public repository, https://github.com/martin-awal/kamus. Forks must change it to their own.
- Indonesian definitions come from a setting (`kamus-idsrc`: `wikt` default | `kbbi-web` | `kbbi-api`; Settings -> Indonesian definitions). `wikt` = id.wiktionary.org read by the BROWSER (`idwiktLookup`/`idwiktParse`: DOM parse of action=parse HTML, definitions from the `<ol>` after each `.section-header-def`, examples = the italic line after `<br>`, else quotations from 1972 on). KBBI is opt-in and server-side only: `/api/lookup?q=&src=web|api` (kbbi.py scraper | `kbbi_api.py` talking to `KAMUS_KBBI_API_URL`, never a URL from the browser); `src` is required, `/api/kbbi/status` tells the page what is available. Entry shape for every source: `{headword, syllables, ipa?, exactIpa?, senses:[{pos:[codes], definition, examples}]}`. The Anki field is still called `KBBI` (and the template says 'KBBI:') whatever the source; only the card sheet label says 'Indonesian'.
- Test servers: always kill the throwaway server on failure paths (a stale one on the same port once served old code and cost an hour).
- Stemming without KBBI: `static/stemmer.js` (`KamusStem`, Nazief-Adriani/Sastrawi-style: particles, possessives, -i/-kan/-an, up to two prefixes with sound changes, reduplication; every path is generated and only stems found in the word list count; ranking = deepest known stem, then fewest put-back letters; stems need 2+ vowels). The word list = single lowercase titles of en.wiktionary `Category:Indonesian_lemmas` + `non-lemma_forms` (about 24.6k words), downloaded on request (`wlDownload`, about 40 s, 50 sequential API calls) into IndexedDB key `wordlist:v1`. Used in `go()` (fallback to the base word when the Wiktionary source has no entry; 'Word parts' line for words that are not themselves in the list) and in the quick-look sheet. KBBI sources keep their own server-side stemming (`kbbi.stem_candidates`). Tests: `node --test tests/*.test.js` (69 cases; keep decoys such as `lajar` in the test list).
- CI (`.github/workflows/ci.yml`): stemmer tests, JS/Python syntax, `scripts/check_credits.py`, a private-data scan (no .db/models/vendor/emails/Google keys tracked), `scripts/smoke_test.sh` (server + static files + auth.html without COOP + KBBI never contacted without `src`), and a job that runs `scripts/fetch_vendor.sh`. Run the same commands locally before pushing. Community files: CONTRIBUTING, SECURITY (private reporting), CODE_OF_CONDUCT (Contributor Covenant 2.1), issue/PR templates, dependabot (monthly).
- Tests (`node --test tests/*.test.js`, 92 cases): `stemmer`, `cards` (cards-store rules, hashes), `sync` (history merge, two devices and one fake cloud, config share links), `apkg` (builds a package and reads it back; skipped without static/vendor). `tests/helpers/shims.js` = in-memory IndexedDB/localStorage; `loadDevice()` gives each simulated device its own database (call `dev.use()` before touching a device).
- No-server mode: `serverUp` (probe of `/api/kbbi/status` at start; a static host that answers with HTML counts as 'no server'). With `noServer()`: default voice = browser, `speak()` goes straight to the browser voice, edge/Wikidepia/Argos/LibreTranslate/KBBI options are locked (`#serverCard` explains), `audioSpec()` returns null for server voices (no audio URL AnkiConnect cannot fetch). New code must not assume `/api/*` exists. `tests/e2e/static-site.e2e.js` (Playwright, mocked Wiktionary/Tatoeba, python file server) guards it; `scripts/build_static.sh` builds `dist/`.
